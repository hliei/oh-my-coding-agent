# 32 — Stream DeepSeek SSE incrementally

**What to build:** Replace whole-response buffering at the private DeepSeek SSE boundary with incremental delivery through the existing public Models and Product Session seams. A complete text or Tool SSE event must become observable without waiting for HTTP EOF, and cancellation after a delivered text delta must settle a response whose transport is still active. Preserve strict parsing, terminal Usage, and Ticket 31's nested cleanup guarantees, then regenerate all Candidate-bound release evidence.

**Blocked by:** 31 — Shield nested DeepSeek cancellation cleanup.

**Status:** resolved

- [x] A deterministic regression against the public installed-wheel seam delivers a complete text SSE event, holds the response open at a later read, and observes the corresponding text delta before releasing HTTP EOF; the current `await response.aread()` implementation fails this test.
- [x] The shared Adapter consumes response bytes incrementally and forwards complete text and Tool events as they become available, without retaining the whole raw response until EOF or introducing a public transport/parser hook. Partial wire frames remain private until valid, and all four Models helpers preserve their existing request and terminal-result contracts.
- [x] Equivalent valid SSE inputs split across network chunks, including UTF-8 code points, LF/CRLF event separators, and JSON payload boundaries, produce the same ordered public observations and terminal values. Partial frames are neither prematurely decoded nor silently dropped.
- [x] Nullable ordinary-chunk Usage, zero-Usage partials, fragmented Tool Calls, the accepted terminal Usage layouts, and strict finalization retain their existing semantics. Missing, malformed, duplicate, inconsistent, truncated, and forbidden post-terminal payloads still fail closed; incremental delivery does not invent defaults or waive a terminal obligation.
- [x] A barrier-driven Product Session regression observes a text delta while the response has not reached EOF and a later transport read is pending, then calls `session.abort()`. Cancellation stops and drains that operation, delivers exactly one aborted Assistant `MessageEnd` with the corresponding Run completion, reaches idle only after cleanup, and permits a fresh successful Run in the same Session. Buffered replay after HTTP EOF cannot satisfy this case.
- [x] Ticket 31's response/client/transport/TLS-equivalent cleanup protection remains intact under later cancellation, repeated aborts, cancelled waiters, and disposal. Direct-helper cancellation preserves its original `CancelledError` after cleanup; managed cancellation retains its accepted terminal contract; genuine cleanup failure remains a distinct fail-closed lifecycle carrier rather than a forged successful cancellation.
- [x] No automatic request retry, reconnect, or replacement operation is added, and public events, errors, and retained evidence expose no credential, authenticated request data, raw Provider response, or internal traceback. The caller-started post-settlement reuse Run remains distinct from a retry.
- [x] Deterministic tests use causal event barriers and bounded watchdogs rather than timing sleeps or busy polling. Installed-wheel conformance exercises both pre-EOF incremental delivery and active-transport cancellation/reuse, with the required Matrix/corpus bindings; a source-only test or runner-only mock cannot substitute.
