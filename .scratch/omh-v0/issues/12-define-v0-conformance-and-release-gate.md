## Answer

v0 has one fail-closed release gate. A release is authorized only for one exact Candidate Wheel after its closed evidence inventory, fixed-Reference oracle, installed-artifact conformance, four supported platform rows, real DeepSeek evidence, and human publication approval all bind to the same release-candidate commit. Passing a subset, running from a checkout, obtaining an available dependency artifact, or observing that an unsupported environment happens to work creates no release claim.

### Evidence authority and coverage

The **Conformance Obligation Matrix** is the sole coverage index. Every entry has a stable obligation id, local decision authority, selected Public Interface or Command Mode where applicable, canonical scenario and A/L/T/E/C observations, comparator and normalization, evidence class, and one or more executable case ids. Case ids are unique; every case points back to an obligation, and every obligation has its required evidence.

Authority is closed to three classes:

- `exact-parity` requires fixed Reference Revision citations and a Reference Observation Corpus case;
- a named `PA:*` or `ABD:*` requires the complete authoritative Parity Ledger record, fixed-Reference citations, and paired Reference/omh expectations; and
- `local-release` requires a local decision authority and Reference `not_applicable` with exactly one reason: `product-scope`, `packaging`, `platform`, or `release-process`.

The Matrix fails closed on a missing or mismatched authority, comparator, observation, evidence class, or case; an orphan case; an uncovered selected public name/member/path; an uncovered required journey or platform obligation; a duplicate or incomplete Ledger key; or any known unresolved Parity Gap. A local release policy never receives a fabricated Pi comparison. Surface Exclusions create no parity promise, but the installed-distribution allowlist cases still prove that excluded public paths and names are absent. Test names, line coverage, an available wheel, and implementation-only assertions are never sufficient evidence.

The Matrix must include every selected Public Import Surface name and member; every applicable `Verification` clause in the resolved decisions governing Behavioral Parity, public interfaces, async/lifecycle, values/schemas/errors, Provider/authentication, Agent/Tool lifecycle, AgentSession, Extensions, coding Tools/Workspace, and REPL/run modes; every required product-journey and companion scenario; every complete `PA:*` and `ABD:*` record; the accepted Python dependency and packaging obligations; and every obligation in this answer. This decision adds no PA or ABD because its rules govern evidence, packaging, supported rows, and release authority rather than changing an accepted runtime observation envelope.

### Fixed Reference oracle

The committed **Reference Observation Corpus** is the deterministic parity oracle. Every record contains canonical input, normalized Reference A/L/T/E/C observations, comparator, fixed revision `0e6909f050eeb15e8f6c05185511f3788357ddb3`, exact source or test citations, and a capture case id. Exact-parity cases compare omh observations to that record. PA/ABD cases retain the Reference observation and separately authoritative omh expectation. Current omh output may never be re-recorded to make a failure pass.

One non-product **Reference Capture Row** runs on the macOS 26 arm64 release workstation. It pins the official Node.js 22.19.0 binary by SHA-256 and its bundled exact npm version, starts from a clean Git export of the fixed revision, and performs `npm ci` strictly from that revision's `package-lock.json`. It then disables external network, supplies no real credentials, and runs only the selected deterministic capture harness. Two independent clean-directory captures must reproduce the committed corpus byte for byte. The actual macOS point release/build plus Node, npm, binary, lock, harness, and corpus hashes enter the Release Evidence Bundle. This evidence environment is neither an omh Runtime dependency nor a product support row.

### Deterministic conformance

The **Deterministic Conformance Suite** drives only the installed Candidate Wheel through the Public Import Surface and `omh` Command Modes. It does not import the source checkout or call implementation functions. Time, entropy, UUIDs, Model transport, and injected failures are controlled only through private internal seams; no public test hook is added. Assertions observe public values, events, errors, transcript/status bytes, durable recovery behavior, or effects in an isolated temporary environment.

Session leases, SQLite, literal file behavior, real subprocess trees, signals, and terminals use real OS resources on the applicable Release Row rather than fakes. Provider wire/protocol cases use in-process fixtures or loopback only; the suite makes no external network request. It permits no skip, xfail, flaky retry, wall-clock sleep, or test-order dependency. Explicit barriers drive races and concurrency. A bounded watchdog may expose a hang only as failure and may not change product semantics.

The mandatory deterministic evidence includes:

- installation metadata, all three closed import allowlists, exact public members and signatures, absence of excluded re-exports/aliases, all four low-level loops, and the sole `Agent.continue_()` name adaptation;
- the complete bounded verified-code-change journey through both the REPL and programmatic `AgentSession`, using nominal `deepseek-v4-flash`, the non-secret environment canary `DEEPSEEK_API_KEY=omh-conformance-canary`, and a private local transport fixture with no external request, including inspection, mutation, a named post-mutation check, truthful report, ordered streaming observations, and terminal outcome;
- distinct recoverable Tool failure, cancellation followed by reuse, deterministic Provider failure followed by reuse, missing-authentication, busy-input rejection, completed-session recovery, one project Skill, and one project Python Extension scenario;
- lazy async activation, EventStream ownership/consumption/result settlement, read-only cancellation signals, callback snapshots, Run cancellation cutoffs, Tool scheduling, atomic Session construction, and retryable fail-closed disposal;
- every admitted Public Value Record, absence/null/numeric-carrier distinction, canonical JSON byte and decode rules, Tool Schema/Pattern validation, strict Tool callable behavior, Tool Call JSON finalization, deterministic redacted validation, and closed error carriers;
- exact DeepSeek request preflight, non-thinking wire bytes, text and fragmented Tool streaming, finish/failure/Usage classification, environment-key re-read, cancellation, zero retry, secret redaction, and post-failure reuse through fixtures;
- complete Run/Turn/Agent event and state traces, strict prompt and Tool Call admission/correlation, Tool Outcome versus Tool Failure classification, redacted runtime errors, immutable loop Context, AgentEnd/result identity, idle ordering, and non-idle state while owned work is unconfirmed;
- Product Session identity, logical cwd, fixed Model, Prompt Resources/templates/system prompt, durable-before-visible commit order, atomic Image publication, exact-id settled recovery, storage failure closure, exclusive lifetime lease, cleanup, and fresh-versus-recovery resource rebinding;
- project-trust zero-enumeration behavior, deterministic Extension discovery, Python entrypoint mapping, fixed registration, immutable snapshot context, handler/effect cutoff, fresh module generations, atomic initialization, reverse retryable shutdown, and explicit arbitrary-side-effect/non-sandbox limits;
- canonical `read`, `bash`, `edit`, and `write` registration/order/schemas/descriptions; literal paths; strict text/pagination; exact edits and write bytes; same-file mutation serialization; actionable negative Outcomes versus real Tool Failures; host shell environment; output merge/truncation/spill; timeout, signal, cancellation, process-tree settlement, and Extension collision behavior; and
- complete CLI grammar and pure help/version actions, TTY/source admission, trust prompt, exact-id selection, REPL transcript/controls/busy behavior, one-shot bytes/status, signal settlement, unique disposal, redacted diagnostics, and recovery continuity.

### Release authorization and publication

One immutable **Release Evidence Bundle** binds:

- release-candidate commit and Distribution version;
- Candidate Wheel filename and SHA-256;
- Release Toolchain Manifest, `uv.lock`, Conformance Obligation Matrix, Reference Observation Corpus, and capture-harness hashes;
- clean double-build and fixed-Reference double-recapture results;
- all four Release Row environment, wheelhouse, clean-install, and deterministic-conformance results;
- redacted Live Provider Gate evidence and named-human approval; and
- machine-checked closure of every selected public surface, required journey, local release obligation, and `PA:*`/`ABD:*`, with zero known unresolved Parity Gaps and zero orphan cases.

No failure, skipped case, unsupported source build, stale live result, or missing obligation may be waived. After reviewing the successful Bundle, the named human creates annotated tag `v<distribution-version>` at the exact bound commit and records the Bundle and Candidate Wheel hashes in the tag. That tag alone grants the Publish Right.

Publication uploads only the already verified Candidate Wheel named by the Bundle. It never rebuilds, replaces, or supplements it with an sdist or another wheel. A changed commit, wheel byte, lock, toolchain manifest, Matrix, corpus, capture/live contract, or evidence invalidates authorization and requires the complete gate plus a fresh human tag.
