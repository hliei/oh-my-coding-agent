## Answer

v0 maps the Reference Revision onto **owner-managed lazy asyncio operations**. Starting, observing, cancelling, and settling an operation are distinct rights. The module that creates an operation owns its task, mutable cancellation controller, terminal classification, and cleanup barrier; public callers receive only the selected awaitable, stream, listener, or read-only signal carriers.

### Observation envelopes

- Selected Promise-returning functions and methods cover A/L/T/E; stateful `Agent` and `AgentSession` operations also cover C. Python call-versus-first-await is normalized only by `PA:python-async-resource-carriers`.
- `EventStream` and `AssistantMessageEventStream` cover A/L/T/E/C, including activation, consumer admission, event order, result projection, cancellation, close, and post-settlement use.
- `AbortSignal` covers A/L/T/C for observation admission, monotonic abort observation, waiter completion, and retained-handle behaviour; it owns no E.
- `AgentEventSink`, `Agent.subscribe()`, and `AgentSession.subscribe()` cover A/L/T/E/C for callback admission, ordered delivery, failure ownership, effect cutoffs, unsubscribe, and later reuse.
- Tool batch scheduling covers A/L/T/E. Scheduler interleavings remain outside the envelope except for the source-order, causality, start-cutoff, and settlement barriers explicitly selected below.
- `Agent` Run admission/idle and Product Session creation/disposal cover A/L/T/E/C. [Choose the AgentSession surface](08-choose-agent-session-surface.md) retains persistent-store transaction and rollback semantics; [Choose the Python Extension lifecycle](09-choose-extension-lifecycle.md) retains Extension-side-effect semantics.

[Choose the values, schemas, and errors contract](05-choose-values-schemas-errors-contract.md) owns the exact Python exception classes, event members, and payload representations for the failure classifications fixed here.

### Async activation and operation ownership

Every selected Reference Promise-returning operation is represented by a lazy Python coroutine or awaitable. Calling it performs no admission, state change, or external effect; its first await starts it. Public methods do not return pre-scheduled `asyncio.Task` objects. Callers may explicitly use `asyncio.create_task()`, while modules may create private tasks only when their owned lifecycle requires one.

`stream()` / `streamSimple()` and `agentLoop()` / `agentLoopContinue()` are synchronous, effect-free factories returning dormant streams. The first `__aenter__()`, `__anext__()`, or `result()` atomically activates the producer once. Concurrent starters share that producer. Closing before activation creates no effect. Comparison maps a Reference eager stream call to the omh factory plus first awaited use.

### EventStream

An activated stream has one producer, one terminal settlement, one consuming-iterator right, and any number of result observers:

- The first iteration claims the consuming right. A second consumer fails before receiving an event; events are never scheduler-partitioned between consumers.
- The sole consumer reads a lossless, unbounded in-memory FIFO. Production never waits for it and never drops, coalesces, or overwrites events. A consumer may start after settlement and drain the complete queue, including its terminal event.
- `result()` observes the same settlement without consuming events and may have multiple waiters. Terminal-event commit may complete `result()` before the consumer reads that event.
- Cancelling any task awaiting `result()` cancels the shared Stream, drains cleanup, and then re-raises `asyncio.CancelledError` in that task. Other result waiters observe the shared terminal result. A previously committed terminal result wins a cancellation race.
- Every conforming activated producer settles exactly once as normal, error, or aborted. An active consumer receives the matching terminal event last. Producer rejection or cancellation is caught and translated by the owning module rather than escaping from a detached task. An early-exited consumer receives no later terminal event, while result observers retain the shared settlement.

`EventStream` is an async context manager with idempotent `aclose()`. Early close, context exit, or consumer-task cancellation requests producer cancellation and shields cleanup to settlement; normal exhaustion releases the buffer. Close or cancellation relinquishes unread events. Result-only callers close the Stream when they no longer need its buffered event history.

A cancellation request commits `aborted` only after all owned cleanup succeeds. Cleanup failure produces lifecycle-cleanup failure; work that cannot confirm settlement remains unsettled rather than allowing a synthetic terminal state. For `__aexit__()`, a body exception remains primary, close failure is retained as an additional cause, and neither rewrites an already committed Stream terminal classification. Body `CancelledError` follows the same cleanup-before-reraise rule.

### AbortSignal and Run cancellation

`oh_my_llm.AbortSignal` is a factory-produced read-only observer with only `aborted: bool` and lazy `wait() -> Awaitable[None]`. It has no public constructor, controller, mutation, reason, or listener API. One active Run supplies the same instance through `Agent.signal`, Agent listeners, `StreamFn`, and Tool execution; `Agent.signal` is `None` while idle. `oh_my_core` imports but does not re-export it.

Only the private owner changes the signal, monotonically from false to true and at most once, before waking all current waiters. `wait()` returns immediately when already aborted. Cancelling one signal waiter removes only that observer and never cancels the Run or other waiters. Normal Run settlement leaves a retained signal un-aborted. This pure observation is the explicit exception to operation-owner awaitable cancellation propagation.

No selected request option or low-level loop entry accepts a caller-supplied signal, and v0 exposes no `AbortController`. Callers request cancellation only through `EventStream.aclose()`, cancellation of an operation-owning awaiting task, `Agent.abort()`, or `AgentSession.abort()`.

`Agent.abort()` is a synchronous, non-waiting request; `waitForIdle()` is the Run settlement barrier. Cancelling the caller task awaiting `prompt()` or `continue_()` requests the same Run cancellation, shields and drains settlement to idle, then re-raises `CancelledError`. `AgentSession.abort()` composes request and settlement.

Abort during an ordinary listener flips the signal immediately and completes the current fixed listener snapshot; later recipients see the aborted signal. Afterwards only cancellation cleanup and downstream-defined aborted terminal events may proceed. Terminal classification commits before its terminal-listener snapshot. Abort after that cutoff is a no-op and cannot rewrite the signal, event, or result, although public completion still waits for terminal listeners and cleanup.

Signal abort is a request, not proof of aborted settlement. Cleanup exception produces lifecycle-cleanup failure for shared observers and waiting cancellation APIs. A caller-task cancellation remains the primary `CancelledError` with cleanup failure retained as cause. A non-settling owned task or resource keeps the operation non-idle.

Callback `CancelledError` classification is provenance-sensitive: a cancellation actually pending on the owner task cancels the operation, including a callback's explicit cancellation of that task; merely raising `CancelledError` without a pending task cancellation is callback lifecycle failure. A callback may not swallow delivered owner cancellation and continue ordinary work.

### Listener and sink barriers

`Agent` and `AgentSession` use the same listener contract. A listener returns `None` or `Awaitable[None]`. For each event, the owner first reduces public state, takes a fixed registration-order snapshot, then sequentially awaits every member before another event or external effect. Subscribing or unsubscribing during dispatch affects only later events. Terminal listeners are part of prompt, idle, and Session settlement. Raw EventStream consumption remains observational and never blocks its producer.

Every `subscribe(listener)` call creates an independent registration, including repeated registration of the same callable. Each unsubscribe closure removes only its own record and is idempotent. Session disposal turns old closures into no-ops.

The first listener exception marks the operation failed and prohibits later events or effects, but the remaining current-snapshot recipients still run in order. The first exception is primary and later exceptions remain ordered additional causes. Cleanup and idle restoration precede the public listener-failure carrier. Failure is never redispatched through the same listener channel.

Within a listener's dynamic dispatch scope, a same-owner settlement-dependent call such as `waitForIdle()`, new `prompt()` / `continue_()`, `AgentSession.abort()`, or `dispose()` fails immediately before state change or effect. Non-waiting `Agent.abort()`, state reads, and subscribe/unsubscribe remain allowed; other owners are unaffected.

`AgentEventSink` likewise returns `None` or `Awaitable[None]` and is invoked exactly once per low-level event. `runAgentLoop*()` awaits it before any later event or effect. Sink failure stops ordinary progression, sends no later event to the failed sink, settles owned work, and then raises distinct event-sink lifecycle failure. A sink may not leak background work or indefinitely suppress cancellation.

### Tool concurrency and cancellation

`AgentOptions.toolExecution` and `AgentLoopConfig.toolExecution` default to `"parallel"`; explicit `"sequential"` serializes a complete assistant Tool batch. If any called Tool has its downstream-owned sequential declaration, the whole batch is sequential. There is no third or adaptive mode.

For a parallel batch, lookup, argument validation, and every other effect-free preflight step run in Tool Call source order, and no Tool callable starts until the entire preflight finishes. Approved calls then start concurrently. Each Tool preserves its own start/update/end causality; cross-Tool completion may interleave. Every started Tool settles before Tool Results are projected in original Tool Call order and before the next Model effect. Failure retains its source-order result slot.

Cancellation is a hard start cutoff. During preflight it stops remaining preflight and starts no Tool. After start it cancels every owned Tool task, admits no further updates or Tool/Model effects, and drains all started tasks, accepted updates, subprocesses, streams, and other resources before aborted settlement or idle. A Tool that suppresses cancellation or leaves background work violates the Tool contract; [Choose the coding Tools and Workspace contract](10-choose-coding-tools-and-workspace-contract.md) must make built-in cooperation executable.

### Agent and Product Session lifecycle

On first await, `Agent.prompt()` / `continue_()` perform effect-free validation and atomically install one Run, its signal, and busy state before suspension or effect. Exactly one concurrent admission wins; losers fail busy and are not queued. Idle commits only after Run, Tool, update, terminal-listener, and cleanup settlement, with signal cleared and public runtime state normalized. State commits idle before waking prompt, continuation, and idle waiters.

`waitForIdle()` captures only the Run present on its first await and returns immediately if already idle; it never waits for a later Run. `abort()` affects only the Run active at its synchronous call and is an idle no-op. Cancellation before coroutine activation creates no Run; cancellation after admission drains that Run.

`createAgentSession()` constructs privately. Every acquired resource immediately registers reverse-order cleanup and remains construction-scope-owned until all required initialization succeeds and one commit transfers ownership into the published `CreateAgentSessionResult`. Failure or cancellation before delivery exposes no usable Session and drains cleanup. Cancellation after internal construction but before delivery first disposes the new Session. Ordinary creation failure remains primary, with cleanup failures ordered beneath it. [Choose the AgentSession surface](08-choose-agent-session-surface.md) and [Choose the Python Extension lifecycle](09-choose-extension-lifecycle.md) retain persistent-state and Extension-effect rollback rules.

`AgentSession.dispose()` is a lazy asynchronous barrier and `AgentSession` is an async context manager. First await atomically enters closing, rejects new Runs and registrations, cancels and settles active work, then disconnects subscriptions and releases resources in fixed order. Concurrent callers share an attempt. Caller-task cancellation shields the attempt before re-raising; `__aexit__()` never suppresses its body exception.

Every independent cleanup action is attempted. A failed attempt leaves the Session internally closing, non-idle, and permanently closed to admission; it raises disposal lifecycle failure with ordered causes. `waitForIdle()` joins the active disposal attempt and receives that same failure. Later `dispose()` retries only unresolved actions. Disposed commits only after confirmed release.
