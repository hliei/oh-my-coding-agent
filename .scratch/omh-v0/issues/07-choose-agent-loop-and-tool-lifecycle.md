# Choose the Agent loop and Tool lifecycle

Type: grilling
Status: open
Blocked by: 03, 04, 05, 06

## Question

What exact turn, event, tool execution, steering, follow-up, continuation, failure, and stop lifecycle must the four loop entry points and `Agent` preserve in v0?

## Comments

- 2026-08-18 — Upstream ordering constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): parallel batches complete all effect-free preflight in Tool Call source order before concurrently starting approved Tools; per-Tool updates/end may interleave, but all started Tools settle before Tool Results are projected in source order and before any next Model effect. This decision owns the exact event and Tool Result shapes.
- 2026-08-18 — Upstream cancellation constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): cancellation during preflight starts no Tool; cancellation after start cancels and drains every owned Tool task, accepted update, and resource before idle, with no later Tool or Model effect. This decision must choose exact retention and terminal semantics for already-completed and cancelled Tool Results.
- 2026-08-18 — Upstream callback constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): `runAgentLoop*()` awaits each `AgentEventSink` invocation exactly once before any later event or effect. Sink failure stops ordinary progression, emits nothing further to that sink, settles owned work, and then raises a distinct lifecycle failure; caller-task cancellation during the barrier settles before re-raising. This ticket owns exact event ordering, and ticket 05 owns the failure representation.
- 2026-08-18 — Upstream admission/idle constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): first await of `Agent.prompt()` / `continue_()` atomically validates and installs one active Run before any suspension or effect; concurrent losers fail busy and are not queued. Idle commits only after complete Run, Tool, update, terminal-listener, and cleanup settlement with public runtime state normalized. `waitForIdle()` observes only the Run present at its first await, and `abort()` affects only the Run active at its synchronous call. This ticket owns exact busy/failure events and state reductions within those boundaries.
- 2026-08-18 — Upstream terminal-cutoff constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): abort during an ordinary-event listener flips the shared signal immediately, completes that event's fixed listener snapshot, and then permits only cancellation cleanup and aborted terminal events. Terminal classification commits before its listener snapshot; later `abort()` is a no-op, while terminal-listener failure may change the public failure carrier but not the committed event/result classification. This ticket owns the exact normal/error/aborted terminal event sequence within that boundary.
- 2026-08-18 — Upstream cancellation-settlement constraint from [Choose the async, stream, and cancellation contract](04-choose-async-stream-cancellation-contract.md): an abort request commits an `aborted` terminal classification only after all owned cleanup succeeds. Cleanup failure produces a distinct lifecycle-cleanup failure, and work that cannot confirm settlement leaves the operation non-idle rather than permitting a synthetic terminal event. This ticket owns the exact Agent/Tool events and retained results for clean abort versus cleanup failure.
