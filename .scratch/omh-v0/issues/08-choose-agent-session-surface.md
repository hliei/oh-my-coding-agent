### Paths, identity, and selection

Path strings are not trimmed or Unicode-normalized. `~`, `~/...`, and `file://` expand; environment variables and `~user` do not. Ordinary relative cwd, Session file, source, and target paths resolve against the call-time process cwd into lexical absolute paths, collapsing dot segments and repeated separators without realpath, symlink collapse, case folding, Unicode normalization, existence checks, or a directory-kind check. Empty cwd resolves to that base directory. Explicit `sessionDir` only performs tilde/file-URL normalization and otherwise preserves relative form for later filesystem interpretation. Tickets 09 and 10 retain trust, traversal, and Workspace Tool-path authority.

The default persistent location is `~/.omh/agent/sessions/--<encoded-cwd>--/<timestamp>_<session-id>.jsonl`. Cwd encoding removes one leading slash or backslash, replaces every remaining slash, backslash, or colon with `-`, and wraps the result in `--`; it neither hashes nor detects collisions. The ISO timestamp replaces colons and periods with hyphens. `create()` ensures the cwd-specific Session directory but leaves the file uncreated until lazy first flush. Explicit `sessionDir` and `open(path)` bypass this default layout.

`NewSessionOptions(id=None, parentSession=None)` is accepted by `create`, `inMemory`, `forkFrom`, and `newSession`. Omission generates UUIDv7. A caller id is preserved exactly, is nonempty, begins and ends with an ASCII alphanumeric, and otherwise contains only ASCII alphanumerics, `.`, `_`, or `-`. Validation precedes manager mutation and persistence effects. Ids need not be UUIDs and are not globally unique across projects, directories, or files. `createBranchedSession()` always generates its new id. `AgentSession.sessionId` is exactly `sessionManager.getSessionId()`.

`create(cwd, sessionDir=None, options=None)` creates a persistent manager. `inMemory(cwd=process_cwd, options=None)` creates the same header/tree/leaf model with `isPersisted() == False`, no Session directory or file I/O, no Session file, and no discovery row; all state disappears at process exit. `newSession(options=None)` resets the current manager to a new header/id and empty tree, returns its candidate file path or `None`, and preserves the manager's cwd, persistence mode, and Session directory.

`open(path, sessionDir=None, cwdOverride=None)` selects cwd from the override, then a valid header, then process cwd, and defaults the manager Session directory to the target's parent. A valid existing file is loaded, migrated, indexed, and treated as flushed. An existing zero-byte file is initialized by immediately rewriting one header. A physically nonempty file that cannot yield a valid Session fails unchanged. A nonexistent path becomes the exact candidate path of a new unflushed Session. `setSessionFile(path)` applies the same existing-empty, existing-valid, existing-invalid, and nonexistent-path behavior to the current manager while retaining its manager cwd, persistence mode, and configured Session directory.

`continueRecent(cwd, sessionDir=None)` scans `.jsonl` files in the explicit or cwd-derived directory. Its fast probe requires the first physical line itself to be a valid Session header with a string id; a custom shared directory also filters by header cwd. It chooses greatest filesystem mtime and opens that file. No candidate, directory error, or probe error yields a fresh lazy Session. Unflushed Sessions are undiscoverable.

Async `list(cwd, sessionDir=None, onProgress=None)` and `listAll(sessionDir=None, onProgress=None)` return `SessionInfo(path, id, cwd, name, parentSessionPath, created, modified, messageCount, firstMessage, allMessagesText)`. Each candidate best-effort parses and fails independently. `modified` uses the latest User/Assistant activity time, then header time, then filesystem mtime; results sort descending. `list` filters header cwd only in a custom shared directory. Default `listAll` scans all cwd subdirectories; custom `listAll` scans that one directory without cwd filtering. Missing or top-level-failed discovery returns empty. Progress counts every processed candidate, including failures. In-memory and unflushed Sessions are absent.

### JSONL persistence and recovery

A Session file is JSONL: one header followed by typed entries. New persistent managers create identity, header, candidate path, index, empty tree, and `flushed=False` in memory but do not create the file. Initial Model/Thinking entries and the first User Message may remain only in memory. The first Assistant Message exclusively creates the file and writes the complete header-plus-entry prefix in order. A crash before this first flush leaves no file or discovery result.

After flush, append first mutates `fileEntries`, id/label indexes, and the manager-local leaf, then appends one JSON line. A write failure propagates raw without rollback, closing, an incomplete marker, or automatic retry. The live manager may continue from an in-memory leaf whose entry never reached disk; a later open sees only parseable persisted entries.

Whole-file rewrite is limited to initializing an existing empty explicit path, applying registered local-format migration, and materializing a selected tree path as a new Session. Rewrites directly truncate and write the target rather than using atomic replacement, and failure may leave a partial file. Ordinary branch, compaction, open/recovery, and append do not rewrite or clean history. Version migration follows the v1-to-v2 tree-id/parent conversion and v2-to-v3 `hookMessage`-to-`custom` role conversion; omh does not promise Pi-file compatibility.

Physical-line parsing is best effort. Blank and malformed-JSON lines are independently skipped while later lines remain eligible. A complete final JSON value is accepted without a trailing newline; a crash-partial final line is skipped. After filtering, the first parsed value must be a Session header with a string id or a physically nonempty file is invalid and left unchanged. Later syntactically valid entries are not uniformly schema-validated at load time.

Recovery rebuilds indexes, labels, tree, and leaf from that parsed sequence. The leaf is the last parsed non-header entry in physical file order. Model context is derived from its active parent path even if the persisted suffix represents an interrupted Run; there is no Session Image, settled marker, or complete-Run admission check. Persisted User, Assistant, Tool, compaction, and other entries survive; an unpersisted tail is lost; malformed lines remain untouched. Recovery never replays an interrupted Model/Tool effect and does not restore busy, queue, steering, follow-up, or retry state. Continued work requires a fresh caller prompt.

Opening or sharing a Session path acquires no exclusive lease. Multiple managers may retain stale local snapshots and append to the same path; exclusive first-file creation is not a continuing lock. v0 provides no owner-busy error, lease lifecycle, timeout, takeover, stale-owner repair, read-only owner, safe multi-writer coordination, or deterministic cross-process ordering. Ticket 04 remains the sole owner of one live `AgentSession`'s active Run, publication, cancellation, cleanup, and disposal.

### Tree, labels, branching, and forking

Every non-header entry has `id`, `parentId`, and `timestamp`. The complete append-only parent graph is authoritative; the current leaf is manager-local and is not separately persisted. `getEntries()` returns every non-header entry in file order. `getTree()` returns every branch, with missing-parent orphans and self-parent entries treated as roots and children ordered by timestamp. `getBranch(fromId=None)` follows parent links to return the selected or current root-to-leaf path. `buildContextEntries()` and `buildSessionContext()` apply branch, summary, compaction, Thinking, and Model projection to that active path. The other accepted read methods expose the current header, leaf, entry lookup, direct children, resolved labels, paths, identity, and Session metadata without creating a second authority.

All append methods create a new child of the current leaf, advance the leaf, and then use the persistence order above. `appendSessionInfo(name)` replaces CR/LF runs with spaces and trims; the latest Session-info entry determines `getSessionName()`, with an empty name clearing it. `appendLabelChange(targetId, label)` requires an existing target and appends a label-set or label-clear fact. Labels decorate tree nodes but remain ordinary append-only entries.

`branch(entryId)` validates the entry and moves the local leaf to it. `resetLeaf()` moves the leaf before all entries. Neither writes or deletes anything. The next append persists divergence through its `parentId`; navigation with no later append is lost on reopen. `branchWithSummary(targetId, summary, details=None, fromHook=False)` first selects the target or root, appends one `BranchSummaryEntry`, and makes that summary the new leaf.

`createBranchedSession(leafId)` extracts the selected root-to-leaf path into a new Session owned by the same manager. It removes label entries, re-chains retained entries, recreates only labels whose targets remain, generates a new id/path, retains cwd, records the prior persistent file as `parentSession`, leaves the source file unchanged, and replaces the manager's current state. A path containing an Assistant Message is written immediately; otherwise it retains lazy first flush. In-memory mode performs the same state replacement without a file.

`forkFrom(sourcePath, targetCwd, sessionDir=None, options=None)` best-effort parses a source with a valid header, exclusively creates a target file immediately, writes a new header with target cwd and source-path `parentSession`, then copies every parsed non-header source entry in file order while preserving ids and parent links. It therefore copies the full tree, not just one branch; the last copied entry becomes the independent returned manager's leaf. The source is unchanged, and target creation is immediate even without an Assistant Message.

`AgentSession.navigateTree(targetId, options)` finds the common ancestor and abandoned path. A User or custom-Message target moves to its parent and returns editable text; other targets become the selected leaf. Without summarization it uses branch/reset. With summarization it requires a Model and appends a branch summary at the new target position, which becomes leaf and context. Its fixed 2,048-token output uses a recent-history budget of context window minus 16,384, includes prior branch/compaction summaries, omits Tool Results, and preserves structured continuation and file-operation facts. Custom instructions either add focus or replace only the branch-summary prompt. Cancellation or failure occurs before leaf mutation; `abortBranchSummary()` cancels the active summary. Agent Messages rebuild from the new active context, and an optional label attaches to the summary or target. Ticket 09 retains Extension tree-hook ownership and does not create another public Session event stream.

### Compaction and overflow continuation

`appendCompaction(summary, firstKeptEntryId, tokensBefore, details=None, fromHook=False)` appends a child without deleting or rewriting history. On the active path, only the latest compaction controls Model context: its summary comes first, followed by the retained pre-compaction tail starting at `firstKeptEntryId` when that boundary exists, then later entries. A missing boundary omits the old tail. Model and Thinking state still resolve from the complete active path, details stay outside Model context, and full pre-compaction history remains available through entries/tree.

`AgentSession.compact(customInstructions=None)` first aborts and settles active Agent work, requires a Model and compactable active path, and rejects immediate repeat compaction or too-small history. It uses the current Model/auth/Thinking/stream seams, appends only on success, rebuilds Agent Messages, and returns `CompactionResult(summary, firstKeptEntryId, tokensBefore, estimatedTokensAfter, details)`. Cancellation or failure appends nothing. `abortCompaction()` cancels manual or automatic compaction; `isCompacting`, `autoCompactionEnabled`, and `setAutoCompactionEnabled()` expose only those accepted controls. Ticket 09 retains compaction-hook ownership.

Compaction defaults are enabled with 16,384 reserve tokens and 20,000 recent tokens. Token accounting starts with the latest valid non-aborted/non-error Assistant Usage plus estimates for later Messages, or estimates all content at approximately characters divided by four. Compaction is needed only when tokens are strictly greater than context window minus reserve. Backward cut search stops only at User/Assistant Messages, retains adjacent non-context metadata, and may separately summarize a split Turn prefix. The latest prior compaction summary is incrementally updated. Fixed structured prompts preserve exact paths, names, errors, continuation state, and inherited/new read/modified-file facts. Optional manual instructions add focus. Normal and prefix output caps are respectively 0.8 and 0.5 of the reserve, bounded by the Model maximum.

Automatic checks run after `agent_end` and before a new prompt. Threshold and successful-over-window responses compact without retry. An overflow Assistant error stays in the complete tree but is omitted from retry context; successful overflow compaction permits exactly one internal `Agent.continue_()` for the same User prompt. A second overflow, or unavailable, cancelled, or failed compaction, settles without another retry. `CompactionStart(reason)` and `CompactionEnd(reason, result, aborted, willRetry, errorMessage)` use `manual`, `threshold`, or `overflow`; only successful overflow recovery reports `willRetry=True`. `AgentEnd.willRetry` follows that one case, and `AgentSettled` occurs only after the complete compaction/retry loop. This adds no Provider retry/backoff, queue, steering, or follow-up behavior.

### Prompt, Agent projection, and listeners

One published `AgentSession` directly composes its `Agent` and caller-visible `SessionManager`. `sessionFile`, `sessionId`, and `sessionName` project the manager's current values. `setSessionName()` appends Session info. `getUserMessagesForForking()` returns file-order User Message entry ids and nonempty text for selection; it does not itself fork or mutate history. `messages` is the current compaction-aware active-path Agent context, not the manager's full tree.

`prompt(text, options=None)` remains the one lazy caller Run barrier. On admission it performs the accepted Prompt Resource expansion, appends the resulting User Message through the manager, and drives the internal Agent with the fixed Model/system prompt/Tools and active Session context. Empty input remains valid. Initial User input may remain unflushed until an Assistant Message; persistence failure follows raw manager continuity rather than closing the Session or establishing a durable settled boundary. Caller-task cancellation still uses ticket 04's complete owned-work settlement before re-raising. There is no public `AgentSession.continue_()`; only the accepted internal one-shot overflow continuation exists.

`AgentSessionEvent` contains `AgentStart`, `AgentEnd`, `TurnStart`, `TurnEnd`, `MessageStart`, `MessageUpdate`, `MessageEnd`, `ToolExecutionStart`, `ToolExecutionUpdate`, `ToolExecutionEnd`, `CompactionStart`, `CompactionEnd`, and `AgentSettled`. `AgentEnd.messages` is the identical Run suffix, never complete Session history. `AgentEnd.willRetry` is true only for successful one-shot overflow recovery. There are no public queue, generic-retry, Thinking/Model-change, entry-appended, Session-info, or tree-navigation events.

`AgentSessionEventListener = Callable[[AgentSessionEvent], None | Awaitable[None]]`. `subscribe()` keeps the accepted strong, ordered, independent registrations and awaited fixed dispatch snapshots. Listener ownership, failure propagation, cancellation, `abort()`, `waitForIdle()`, publication, context management, and retryable live-resource `dispose()` remain ticket 04's contract. JSONL persistence adds no lease or live-resource disposal responsibility.

### Prompt Resources and fixed system prompt
