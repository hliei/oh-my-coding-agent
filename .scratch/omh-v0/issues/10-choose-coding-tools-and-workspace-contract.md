### `bash`

`bash(command, timeout?)` has a closed argument object. Command is passed unchanged and may be empty. Timeout is optional positive finite seconds no greater than `2147483.647`; omission means no Tool timeout. No per-call cwd, env, shell, stdin, login, prefix, hook, or operations override exists.

Each call resolves the pinned Reference shell order immediately before spawn: POSIX `/bin/bash`, then `PATH` bash, then `sh`; Windows Git Bash under the two Program Files roots, then `PATH` bash. Ordinary transport is non-login/non-interactive `-c`; only legacy system-directory WSL bash uses `-s` plus command stdin. Initial cwd is Workspace. Each spawn receives a fresh exact copy of current `os.environ`, preserving existing key spelling and values but adding no `.env`, profile, project, Extension, product variable, or `PATH` rewrite.

Stdout and stderr are unlabeled pipes merged in Runtime chunk-arrival order, preserving per-pipe order but promising no cross-pipe total order. One incremental UTF-8 replacement decoder consumes the merged bytes and performs no stripping, sanitization, or normalization. The displayed result retains the last 2,000 logical lines or 51,200 decoded UTF-8 bytes. A final over-limit line may contribute its UTF-8-safe tail. On truncation, the complete merged raw bytes are written to one unpredictable exclusive owner-only `omh-bash-*.log`; the absolute path remains usable, is not appended to `SessionManager` history or a Session file, and is not automatically deleted.

The exact truncation suffixes are `[Showing last {outputSize} of line {endLine} (line is {lineSize}). Full output: {fullOutputPath}]`, `[Showing lines {startLine}-{endLine} of {totalLines}. Full output: {fullOutputPath}]`, or `[Showing lines {startLine}-{endLine} of {totalLines} (50.0KB limit). Full output: {fullOutputPath}]`, each preceded by two LF after the retained tail. Truncated details is exactly the complete Reference tail `truncation` object plus `fullOutputPath`; untruncated details is JSON null.

`bash` alone emits cumulative updates: one initial empty update, then an immediate first dirty snapshot and coalesced latest snapshots at most once per 100 ms, followed by a last dirty snapshot before ordinary terminal construction. Updates are validated immutable Results, carry no final notice, and stop at cancellation or output-infrastructure failure.

Exit zero returns exact output or `(no output)`, plus the accepted tail notice and details when truncated. Nonzero exit, external signal, explicit timeout, invalid command, unavailable Workspace/shell, denied spawn, and recognized output-pipe/spill failures return the accepted machine-coded actionable Outcomes, preserving verified output and effects where applicable. Timeout begins after spawn, force-terminates the owned process group/tree, and settles all pipes/helpers/files before Outcome. Cancellation overrides every nonterminal classification, kills and drains the owned tree, retains only a spill path already exposed by an accepted update, and uses ticket 07's cancelled Tool Failure. Unconfirmed cleanup never publishes terminal success/Outcome or idle.

The exact appended status texts are `Command exited with code {exitCode}`, `Command terminated by signal {signalNumber}`, and `Command timed out after {timeoutText} seconds`, each preceded by two LF after the ordinary output/tail text. Their details codes are `nonzero_exit`, `signal_exit`, and `timed_out`, with `exitCode`, positive `signal`, or original numeric `timeout`, plus truncation/path when applicable. Pre-spawn texts are exactly `Bash command is invalid`, `Bash Workspace {q(workspace)} is unavailable`, `Bash shell is unavailable`, and `Bash process creation is not permitted`, with code/phase/effect-none details. Output-infrastructure text appends `Command output could not be collected completely` or `Command output could not be saved completely because storage is full` to the verified tail or `(no output captured)`; details is code `output_unavailable|output_storage_full`, phase `pipe|spill_create|spill_write|spill_close`, effect `command_may_have_effects`, and output `partial`, with no ordinary truncation/path members.
