## Answer

### Public surface and Project Resource Trust

The ticket-09-complete `CreateAgentSessionOptions` adds exactly `projectTrusted: bool = False` to the existing `cwd`, `model`, and `sessionId` fields; ticket 10 retains only its reserved Tool-field authority. A non-`bool` carrier raises `TypeError`. Omission or `False` performs no probe, enumeration, read, import, or initialization for project Extensions, Skills, or Prompt Templates and supplies empty project-resource snapshots. `True` admits all three under their owning rules. Every fresh or recovery construction receives a new decision: trust is never persisted in or inherited from the Session Image, an ancestor, a prior Session, or a trust store. The later REPL may obtain the human decision but only passes this same value. Project Resource Trust authorizes project-resource loading, not built-in Tool, command, or filesystem authority.

`oh_my_coding_agent` adds only `ExtensionAPI` and `ExtensionContext` at its root for Extension authoring. Both are final, factory-produced, read-only nominal handles with no public constructor or subclassing. `CreateAgentSessionResult` remains exactly `session`; there is no Extension list, diagnostic bundle, loader, runtime, runner, registry, or direct dependency-assembly escape.

### Discovery, source snapshot, and module generation

When trusted, construction discovers only direct `.omh/extensions/<name>.py` files beneath normalized `cwd`, where `<name>` matches `[a-z][a-z0-9_]{0,63}`. Hidden entries, other suffixes, subdirectories, user/global or ancestor sources, settings/package declarations, manifests, npm/git resources, explicit paths, and inline factories are outside the v0 source set. Missing `.omh/extensions/` means no Extensions. An existing selected `.omh` path and Extension directory must be real nonsymlink directories; each candidate must be a real nonsymlink regular file. A nonhidden direct `.py` file with an invalid name, a path-kind violation, or a discovery/snapshot race rejects the whole construction.

The complete candidate list is fixed before loading and ordered by exact filename Unicode code point. Before any module executes, every source is snapshotted as BOM-free strict UTF-8 bytes without newline or Unicode normalization. Each snapshot becomes an independent Session-private module. The module must define exactly one accepted entrypoint slot: module-level callable `extension`. The loader invokes `extension(api)` exactly once with one positional `ExtensionAPI`; the result must be `None` or an awaitable settling to `None`. There is no signature/dependency-injection/return adaptation, alternate `default`/`setup`/class/decorator/registry entrypoint, or public module identity.

Module execution, entrypoint validation, factory invocation, and complete settlement occur sequentially for each Extension before the next begins. Standard-library and already installed distribution imports use ordinary Python semantics, but omh installs nothing, reads no dependency manifest, and does not add `.omh/extensions/` to `sys.path` as an implicit package. It writes no `.pyc`/`__pycache__` and exposes no reusable `sys.modules` identity for project Extension modules.

One Product Session construction owns one module generation. Module globals remain fixed for the published Session lifetime; later source edits are invisible. A separate fresh or exact-id recovery construction discovers current admitted sources and executes new independent modules and factories. v0 has no watcher, in-place/manual/automatic reload, or generation switch. Successful shutdown drops omh-owned module/API/handler/Tool references; Extension code that leaks references elsewhere remains outside omh's collection guarantee.

### Fixed registration interface

`ExtensionAPI` exposes exactly:

- `on(eventType, handler) -> None`; and
- `registerTool(tool: AgentTool) -> None`.

Both are usable only while their owning `extension(api)` call is active. Factory settlement permanently closes registration; retaining the handle cannot mutate or refresh a published Session. `on` creates one independent registration per call in call order, including repeated use of the same callable, and has no unsubscribe because registrations share the Session lifetime. `registerTool` accepts only an admitted `oh_my_core.AgentTool` identity, which is not re-exported, and accepts no mapping, duck type, or callable shorthand. Extension-to-Extension Tool names must be unique; a duplicate rejects construction. Ticket 10 alone owns built-in/Extension collision, activation, and override policy.

Commands, shortcuts, flags, renderers, Providers, shared event buses, UI, SessionManager, Model/Session actions, arbitrary system-prompt append, cleanup registration, and every other Reference registration family are Surface Exclusions. The fixed Product Session system prompt receives no Extension-controlled append; registered Tool definitions reach the Model only through the later-admitted Tool set.

### Events, context, and dispatch

The closed `eventType` set is `session_start`, `session_shutdown`, `agent_start`, `agent_end`, `turn_start`, `turn_end`, `message_start`, `message_update`, `message_end`, `tool_execution_start`, `tool_execution_update`, `tool_execution_end`, and `agent_settled`. The eleven Agent names deliver the exact matching already selected `AgentSessionEvent` variant rather than a second Extension event model. Session lifecycle handlers receive only their context; Agent-event handlers receive the matching event then their context. Every handler must return `None` or an awaitable settling to `None`.

`ExtensionContext` is a fresh immutable invocation snapshot containing normalized `cwd: str`, canonical `sessionId: str`, lifetime-fixed `model: Model`, `messages: tuple[AgentMessage, ...]` as the largest-confirmed-durable prefix at handler entry, and `signal: AbortSignal | None`. Agent events receive the active Run's same read-only signal; Session lifecycle events receive `None`. A retained context remains readable but never updates and exposes no abort, prompt, wait, reload, Session/Model switch, UI, manager, registry, Provider transport, or history mutation authority.

After every AgentSession state reduction and required durable-before-visible write, matching Extension handlers run sequentially by Extension discovery order then registration order. Only complete Extension success permits the public `AgentSession.subscribe()` listener snapshot and any later event or Model/Tool effect. A handler failure stops later handlers/listeners and ordinary progression, settles started owned work, and raises exact `LifecycleError(code="hook", message="Python Extension handler failed", causes=(handler_error, *cleanup_errors))`. Published state/history is not rolled back and no synthetic Tool, Assistant, `AgentEnd`, or `AgentSettled` value repairs the trace. Failure inside an already committed terminal event changes only the await carrier. Confirmed cleanup restores idle/reuse; unconfirmed resources retain the existing non-idle cutoff.

After every factory and the final Tool set succeed, `session_start` runs once in forward order before final system-prompt construction, a fresh Image commit, or Session publication. It is fail-fast; a failing Extension owns its incomplete local acquisition, after which omh shuts down only the completely started prefix. On disposal, `session_shutdown` runs after any active Run completely settles, in reverse Extension and per-Extension registration order. It attempts every applicable handler, requires idempotence, remembers successes, and lets a later `dispose()` retry only unresolved handlers. Explicit disposal aggregates its failures through the accepted `LifecycleError(code="disposal")`; construction rollback keeps the original error primary and appends shutdown errors in execution order. Actual task cancellation shields the same settlement before re-raising.

### Construction failure and arbitrary Extension effects

A selected structural path/name/symlink/source/UTF-8/syntax/missing-or-noncallable-entrypoint violation raises exact `ValueError('Python Extension ".omh/extensions/<name>.py" is invalid')`. An OS source-read failure raises `LifecycleError(code="cleanup", message='Python Extension ".omh/extensions/<name>.py" could not be read', causes=(private_cause,))`. Module top-level execution, dependency import, factory, registration, or factory-result failure raises `LifecycleError(code="hook", message='Python Extension ".omh/extensions/<name>.py" initialization failed', causes=(private_cause, *cleanup_causes))`.

The first construction failure stops later modules, discards all omh-owned Extension modules and registrations, writes no fresh Session Image, leaves a recovery Image unchanged, and exposes neither partial Session nor diagnostics bundle. Actual caller-task cancellation cancels an active async factory, shields owned cleanup, and re-raises `asyncio.CancelledError`; an Extension-raised `CancelledError` is initialization failure. Trusted synchronous code or code suppressing cancellation has no timeout or preemption guarantee.

Extensions execute in-process with the user's process permissions and no sandbox. A conforming factory performs registration only; Session-lifetime resources are acquired in `session_start` and released in `session_shutdown`. Direct filesystem, process, network, environment, or global mutations performed outside the selected lifecycle are Extension-owned and cannot be rolled back. Private-construction atomicity therefore promises omh-owned store, registrations, tasks, and resources, not arbitrary Python external effects.
