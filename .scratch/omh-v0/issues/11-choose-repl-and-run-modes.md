# Choose the v0 REPL and run modes

Type: grilling
Status: resolved
Blocked by: 01, 06, 07, 08, 09, 10

## Question

What observable input, streaming output, tool display, cancellation, queueing, session, shutdown, configuration, and non-interactive behaviour must the simple v0 REPL and any other selected run modes provide without becoming a reusable TUI framework?

## Answer

v0 exposes exactly two **Command Modes** over the existing durable `AgentSession` seam:

- `omh` starts an interactive, append-only plain-text REPL.
- `omh --print PROMPT` or `omh --print` with non-TTY stdin performs exactly one text Run and exits.

Command Mode is a launcher interaction form, not a Run or a second Session abstraction. Neither mode owns Agent state, durability, cancellation, Tool classification, recovery, or lifecycle policy; both adapt the already selected Product Session contract. Non-TTY input or output never implicitly changes mode. JSON/JSONL, RPC, an ephemeral Session, and a reusable TUI package are absent.

### Closed command surface and admission

The complete launcher flag set is `--print`, `--cwd PATH`, `--session-id UUIDV7`, `--trust-project`, `--help`, and `--version`, with no short aliases. Standard `--` ends option parsing. Unknown, repeated, conflicting, or missing arguments are usage failures on stderr with status 2 and no Session or resource effects. No config file or Extension expands this grammar; the sole runtime environment input remains `DEEPSEEK_API_KEY`.

`--help` and `--version` are mutually exclusive pure terminal actions evaluated before TTY, cwd, stdin, trust, credential, store, or resource work. Help is a golden-locked, definition-derived description of the closed surface. Version writes exactly `omh <installed-distribution-version>\n`; missing or invalid installed Distribution metadata is `internal error` with status 1. Either action combined with any other action, run flag, `--`, or prompt is a usage failure.

Interactive mode requires TTY stdin and TTY stdout; stderr may be redirected. Failure tells the caller to use `--print` and exits 2. One-shot has no stdout-TTY requirement. It accepts exactly one normalized source: one positional `PROMPT`, or the complete strict-UTF-8 non-TTY stdin through EOF when the positional prompt is absent. Positional input plus non-TTY stdin, TTY stdin without a positional prompt, an empty ECMAScript-trimmed source, extra messages, or invalid UTF-8 fails before Session construction with status 2. There is no `@file`, message concatenation, multiline editor, shell-input shorthand, or autonomous subsequent Run.

### Construction, identity, recovery, and trust

One package-private preflight module is shared by the launcher and `createAgentSession()`. After syntax, TTY, and source admission, the launcher captures process cwd once; resolves omitted or relative `--cwd` to the same logical absolute existing directory; and validates an optional canonical UUIDv7. The public factory revalidates the supplied absolute cwd, exact id, and boolean trust value through the same rules without recapturing process cwd. Preflight performs no credential, store, lease, `.omh`, Prompt Resource, or Extension effect. A validly carried but invalid cwd or id is a Product Session admission `ValueError`, reported with status 1 rather than usage status 2.

Omitting `--session-id` creates a new durable Session under a privately generated UUIDv7. Supplying it is recovery-only: the exact same-cwd settled Image must exist and be resumable. An absent, cross-cwd, invalid, incomplete, or already owned identity is rejected; it is never used to create a replacement. There is no recent/continue/picker, caller-selected fresh identity, open-or-create, fork/tree/list, automatic recovery, or ephemeral mode.

Interactive construction without `--trust-project` writes and flushes exactly `Trust project resources in "<field-encoded-cwd>"? [y/n] ` to stdout. After ECMAScript trim, only a case-insensitive single `y` or `n` is accepted. Other input writes `Please enter y or n.\n` and retries. `--trust-project` skips the prompt and supplies `projectTrusted=True`; `n` supplies `False`. Ctrl-C writes `trust cancelled\n` and exits 130, while EOF writes the same text and exits 0; neither constructs a Session. One-shot never prompts: the flag means true and omission means false. Trust is obtained anew for fresh and recovery construction, is never saved or inferred, and grants only project-resource discovery rather than Tool or workspace authority.

Immediately after Session publication and before any Run, interactive stdout and one-shot stderr write and flush exactly `session <UUIDV7> new` or `session <UUIDV7> recovered`, followed by LF. The record exposes no history or recovery command. If it cannot be written, no Run starts; the launcher disposes the published Session and exits through the I/O-failure path.

### Interactive input and continuity

The REPL owns one lifetime stdin reader and at most one prompt task. Idle chrome is exactly `> `. Each Enter supplies one strict-UTF-8 line, ECMAScript-trimmed. Empty input is a local no-op; nonempty input is passed unchanged after normalization to exactly one `AgentSession.prompt()`. There is no launcher command namespace: `/skill:<name>` and `/<name>` retain Prompt Resource semantics, while `/quit`, `/help`, `/resume`, `/new`, `!`, and `!!` are ordinary prompt text unless the existing Prompt Resource grammar classifies them.

The reader remains active while a Run is active. Until prompt settlement, terminal-record flush, and the serialized return to idle all complete, every nonempty input line is discarded with exact stderr `busy: Product Session has an active Run`; empty lines remain no-ops. There is no steering, follow-up queue, queued restoration, history, completion, or cursor-restoration policy.

Blank and busy admission, verified pre-Run `ValueError`, a normally returned model error, ordinary Tool Outcome or recoverable Tool Failure, and confirmed cancellation return to the same idle Session. A `LifecycleError`, stdin/stdout/renderer I/O failure, or unexpected non-cancellation exception permanently closes admission, disposes, and exits 1. A purported pre-Run `ValueError` whose observed state or effects contradict admission fails closed. No Model, Provider, Tool, Extension, listener, persistence, or cleanup failure is retried automatically.

### Interactive transcript

The REPL is one sequential awaited `AgentSession` listener and an append-only UTF-8 transcript. It never redraws prior output. Each output-bearing event is written and flushed before the listener returns, making terminal slowness bounded backpressure rather than a private queue, drop, or coalescing policy.

The exact stdout grammar after the identity record is:

```text
assistant start
<incremental Assistant Text>
assistant end
tool start name="<field>" id="<field>" arguments=<canonical-json>
tool outcome name="<field>" id="<field>" result=<canonical-json>
tool failure name="<field>" id="<field>" result=<canonical-json>
run completed
run model_error
run cancelled
```

`MessageStart` writes and flushes `assistant start`. Each cumulative, append-only `MessageUpdate` contributes only its newly observed nonempty Text suffix and flushes immediately. `MessageEnd` inserts one LF when the body does not already end in LF, then writes and flushes `assistant end`; an empty Assistant message still has both markers. Tool Call content inside Assistant messages is not body text.

Tool start records the public name, id, and arguments. Tool end is `tool outcome` for every `AgentToolResult.isError=False`, including a valid negative domain result, and `tool failure` only for `isError=True`. The exact final result object is `{"content":[<text>...],"details":<JSONValue>,"terminate":<bool-or-null>}`. Tool updates, Turn events, raw Agent start/end, and private causes are not rendered. Parallel Tool records retain public event-arrival order. Each Tool record is one atomic write and flush.

Only after `AgentSession.prompt()` returns normally at the durable-idle boundary does the renderer append exactly one `run completed`, `run model_error`, or `run cancelled`. These are the sole interactive terminal carriers; model error and cancellation are not duplicated on stderr. A lifecycle failure fabricates no Run terminal record. Listener encode/write/flush failure follows the existing `LifecycleError(code="listener")` path: committed facts remain, later progression stops, the Session is disposed, and the launcher exits 1 without replay.

### Terminal-safe encoding

All launcher input and output is strict UTF-8. Body encoding preserves LF, TAB, and ordinary Unicode scalar values, but visibly escapes CR, ESC, other C0 controls, DEL, C1 controls, and bidirectional format controls as uppercase four-hex `\uXXXX`. Field encoding additionally escapes LF, TAB, quotation mark, and backslash so metadata remains one record. ANSI, OSC, color, and hyperlinks are never interpreted.

Tool arguments and structured results use compact Unicode-key-sorted canonical JSON after the same string-safety transformation; Tool Text uses body encoding. Neither transcript nor diagnostics use Python `repr()`. Encoding, writing, or flushing failures are launcher I/O failures and never reclassify the underlying Run or Tool fact.

### Controls, signals, and shutdown

During an active interactive Run, Ctrl-C calls the existing `AgentSession.abort()`, joins complete settlement, emits `run cancelled` only when cancellation is confirmed, and returns to the same Session. Repeated Ctrl-C while settling joins the same attempt. Idle Ctrl-C only clears the current line and redraws the prompt. EOF/Ctrl-D closes admission and enters orderly disposal; if work is active, disposal owns abort and settlement. Escape, double-Ctrl-C timing windows, force-exit keys, queue restoration, and hard-kill controls are absent.

Interactive SIGHUP/SIGTERM and one-shot SIGINT/SIGHUP/SIGTERM use a terminating path with status 129/143 and 130/129/143 respectively; the first terminating signal fixes the status. HUP or TERM permanently closes interactive admission; a published active Session settles through its sole disposal path and may emit only a confirmed `run cancelled`, while an idle Session emits no Run record. Before Session publication, HUP/TERM and one-shot terminating signals emit `cancelled` on stderr and perform no disposal; interactive trust-prompt Ctrl-C retains its distinct `trust cancelled` rule. Later signals only join the in-progress shutdown and never force it. SIGKILL, host termination, and suspension are outside the contract.

Every published Session is held by the launcher in one `try/finally` and receives exactly one automatic `dispose()` call on ordinary completion, EOF, or signal shutdown. The launcher adds no cancellation timeout or retry. Successful disposal retains the settled durable Image, releases live ownership, and emits no recovery hint. Cleanup failure upgrades an otherwise-zero status to 1, but never replaces a primary signal status; its diagnostic follows the primary. Pre-construction failures do not dispose.

### One-shot output and status

One-shot subscribes to no streaming renderer and buffers terminal Assistant Text until settlement. stdout contains only body-encoded terminal Assistant Text blocks concatenated directly, with no inserted separator or final LF and no Tool or `run ...` records. Confirmed completion exits 0. Confirmed model error may emit retained partial Text, writes `model error` to stderr, and exits 1. Confirmed SIGINT, SIGHUP, or SIGTERM cancellation may emit retained partial Text, writes `cancelled`, and exits 130, 129, or 143. Unconfirmed settlement emits no stdout. A broken stdout after settlement cannot change the Run, is not retried or redirected, and exits 1 after disposal.

Exit 0 means only that the selected Command Mode completed normally. It is not evidence that a modification or named verification check succeeded.

### Closed diagnostics

Every stderr diagnostic is a field-encoded, LF-terminated record from this closed set:

- launcher syntax, TTY, or source admission: `usage: <static reason>`;
- verified pre-Run value rejection: `error: <public message>`;
- lifecycle failure: `lifecycle <code>: <public message>`;
- one-shot model error or confirmed cancellation: `model error` or `cancelled`;
- launcher I/O or unexpected failure: `I/O error` or `internal error`;
- subordinate disposal failure: `lifecycle cleanup: <public message>` after the primary;
- the separately owned busy and trust lines fixed above.

Only stable public messages may fill a template. Diagnostics expose no exception class, `repr`, traceback, cause tuple, errno, raw Provider text, prompt/stdin content, environment value, credential, or secret. stderr failure stops reporting without recursion or stdout fallback. There are no debug, verbose, trace, or implicit-log-file modes.

### Surface exclusions

v0 deliberately excludes JSON/JSONL and RPC modes; `@file` and multi-message launch input; rich TUI rendering, color, Markdown layout, spinners, folding, terminal-width adaptation, widgets, images, custom renderers, and status bars; in-REPL launcher commands and shell shorthand; recent/continue/picker/open-or-create/ephemeral/fork/tree/list Session selectors; steering, follow-up, queue restoration, and autonomous input; Escape/double-Ctrl-C/force-key policies; dynamic plugin/configuration flags; and recovery hints. These exclusions create no Ledger records.
